About This Project

A simple Angular application demonstrating dynamic routing, route parameters, shared services, and data-driven student profiles.

01

Project Overview

What this application demonstrates

This project is built with Angular to demonstrate how different Angular concepts work together in a real application. The main focus is on dynamic routing, route parameters, shared services, and component-based data flow.

The application contains a list of students on the Home page. Each student has their own profile, and the profile can be opened dynamically using the student's unique ID.

03

How the Application Works

Complete data flow from Home to Profile

Step 1 — Student data is stored in StudentService

Instead of keeping the student data separately inside different components, the application uses a shared StudentService. The service contains the complete list of students and provides methods to access that data.

students = [ ... ];

getStudentById(id: number) {
  return this.students.find(student => student.id === id);
}

Step 2 — Home gets the students from the service

The Home component injects the StudentService and gets the complete student list from it. The students are then displayed as cards using Angular's @for control flow.

constructor(private studentService: StudentService) {
  this.students = this.studentService.students;
}

Step 3 — Home creates a dynamic profile link

Every student card contains a View Full Profile button. The student's ID is added dynamically to the route.

[routerLink]="['/profile', student.id]"

Example

If the student's ID is 102, Angular generates:

/profile/102

Step 4 — Angular matches the dynamic route

The router is configured with a dynamic route. The :id part means that Angular expects a value in that position.

{
  path: 'profile/:id',
  component: Profile
}

Therefore, both /profile/101 and /profile/102 use the same Profile component, but with different IDs.

Step 5 — Profile reads the ID from the URL

When the Profile component loads, Angular's ActivatedRoute is used to read the ID from the URL.

const id = Number(
  this.route.snapshot.paramMap.get('id')
);

For the URL /profile/102 , Angular gives the Profile component the value 102.

Step 6 — Profile finds the matching student

The ID obtained from the URL is passed to the StudentService. The service searches the student array using find() and returns the matching student object.

this.student = this.studentService.getStudentById(id);

Example

URL: /profile/102

↓

Extract ID: 102

↓

Search StudentService: student.id === 102

↓

Rahul Sharma's complete student object

Complete Data Flow

Home → URL → Profile → Service → Student Data

1. StudentService → stores student data
↓
2. Home → gets and displays students
↓

↓

↓

↓

↓

04

Why Use a Student ID?

Using an identifier for dynamic routing

The application uses the student's ID instead of the student's name in the URL. An ID is generally a better identifier because it is expected to be unique and is less likely to change.

Name-based route

/profile/Rahul-Sharma

ID-based route

/profile/102
